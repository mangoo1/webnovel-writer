# 摘要系统 Schema 定义

## 概述

OpenCode 版本使用"滑动窗口摘要"替代 RAG 向量检索，为新章节写作提供上下文。

## 数据流

```
写完章节 → /webnovel-summarize → .webnovel/summaries/ch{NNNN}.md
                                          ↓
每卷完成 → /webnovel-compress → .webnovel/summaries/vol{NN}.md
                                          ↓
写新章节 ← context-agent 读取 ← 最近5章摘要 + 历史卷摘要
```

## 章节摘要格式（ch{NNNN}.md）

```markdown
---
chapter: 0042
title: "悬崖对峙"
time_anchor: "末世第7天 黄昏"
location: "断魂崖"
characters: ["林凡", "张三", "李四"]
pov: "林凡"
word_count: 2300
emotion_arc: "紧张 → 震惊 → 悲壮"
hook:
  type: "悬念钩"
  content: "张三跌落悬崖，生死不明"
  strength: "strong"
ending_state:
  emotion: "悲壮"
  tension: 8
---

## 剧情要点

- 林凡追踪张三至断魂崖
- 张三揭露真实身份：前朝太子
- 张三使用禁术「血焚」，代价是三十年寿命
- 激战中张三跌落悬崖

## 角色变化

| 角色 | 变化 | 原因 |
|------|------|------|
| 林凡 | 愤怒 → 理解 | 得知张三身世 |
| 张三 | 暴露身份 | 被逼至绝境 |

## 伏笔动态

- [新增] 禁术「血焚」来源 → 待回收（紧急度:60）
- [推进] 神秘玉佩发光（第30章埋下）→ 进度 50%
- [回收] 张三失踪之谜（第15章埋下）→ 已闭合

## 关系变化

- 林凡 → 张三: 敌对 → 复杂（亦敌亦友）

## 承接要点

下章需要：
- 交代张三生死
- 处理林凡的情绪转变
- 玉佩发光后续
```

## 上下文组装规则

写第 N 章时，context-agent 读取：

### 必读
1. **最近 3 章详细摘要**：ch{N-1}.md, ch{N-2}.md, ch{N-3}.md
2. **本章大纲**：从大纲文件提取

### 条件读取
3. **最近 5 章摘要**：若章节跨度大（如隔了很久没写），扩展到 5 章
4. **历史卷摘要**：若当前是第 2 卷+，读取之前各卷的 vol{NN}.md
5. **特定伏笔相关章节**：若本章需回收某伏笔，额外读取埋设章节摘要

### 上下文模板

```markdown
# 写作上下文包

## 历史卷概要
{vol01.md 压缩版，约 500 字}

## 最近章节摘要

### 第 N-3 章
{ch{N-3}.md 核心内容}

### 第 N-2 章
{ch{N-2}.md 核心内容}

### 第 N-1 章（上章）
{ch{N-1}.md 完整内容}

## 本章任务
{从大纲提取}

## 需处理的伏笔
{从摘要中汇总的活跃伏笔}

## 上章钩子（必须接住）
{ch{N-1}.md 的 hook 字段}
```

## 字数控制

| 内容 | 目标字数 | 说明 |
|------|----------|------|
| 单章摘要 | 300-500 | 保留关键信息 |
| 卷摘要 | 800-1200 | 压缩 50 章为 1 文件 |
| 上下文包总量 | 3000-5000 | 控制 token 消耗 |

## 与 RAG 版本对比

| 方面 | RAG 版本 | 摘要版本 |
|------|----------|----------|
| 依赖 | 需要 embedding API | 无外部依赖 |
| 召回方式 | 语义检索 | 滑动窗口 + 结构化 |
| 优势 | 能找到远距离相关内容 | 简单、可控、无幻觉 |
| 劣势 | API 成本、偶尔召回不准 | 可能漏掉远距离伏笔 |
| 适用场景 | 超长篇（500章+） | 中长篇（100-300章） |
